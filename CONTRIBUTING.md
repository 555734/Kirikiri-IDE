# Contributing to Kirikiri

## The short version

Fork it. Change whatever you want. Send a PR if you feel like it.

That's it.

## Philosophy

Kirikiri exists to be used and modified. There are no wrong contributions. If a change makes your workflow better, it probably helps someone else too.

You don't need permission to fork and build your own version. That's encouraged.

## Pull Requests

PRs are welcome at any time — no need to ask first. The maintainer will review when time allows and merge what fits the project direction. PRs may sit for a while; that's not a rejection.

For large architectural changes, opening an Issue first helps avoid wasted effort.

## Issues

The maintainer uses Issues to share ideas and wanted features. Feel free to add your own — bug reports, feature requests, and questions are all welcome.

## Code

Run `flutter analyze` before submitting. No other style requirements.
