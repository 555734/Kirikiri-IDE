# 実機確認手順

自動テストで確かめられないもの——プラットフォーム境界、SSH の実通信、
権限フロー、通信断——を実機で確認するための手順。

ビルドは **Device Test Build** ワークフローの成果物 (`android-apk-...`) を
使う。`app-release.apk` は難読化済みで、`app-debug.apk` はログが読める。
**難読化でしか出ない不具合があるため、最終確認は必ず release 版で行うこと。**

---

## 1. ホスト鍵の検証

接続経路そのものを変更しているため、最優先で確認する。ここが壊れていると
アプリが一切繋がらない。

| # | 手順 | 期待する結果 |
|---|---|---|
| 1.1 | アプリを新規インストールし Cloud Shell に接続 | 指紋 (`SHA256:...`) を表示するダイアログが出る |
| 1.2 | 「信頼して接続」を選ぶ | 接続が進み、ターミナルが表示される |
| 1.3 | アプリを再起動して再接続 | **ダイアログが出ない**（保存された指紋と一致） |
| 1.4 | 「接続しない」を選ぶ | 接続されず、赤いエラー表示が出る |
| 1.5 | カスタム SSH サーバー（パスワード認証）で 1.1〜1.3 | 同じ挙動 |

**指紋の正しさの確認**（できれば）: サーバー側で
`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` を実行し、アプリが表示した
文字列と一致することを確認する。

**Cloud Shell の鍵ローテーション観測**: 数日〜1週間使い、
「ホスト鍵が変更されています」の警告が出る頻度を記録する。VM の再作成で
頻発するなら、Cloud Shell だけ別扱いにする設計変更が必要（要相談）。

## 2. GitHub PAT が漏れていないこと

Settings で PAT を登録し、**プライベートリポジトリ**を Shell で開いてから確認する。

| # | 確認コマンド（リモートで実行） | 期待する結果 |
|---|---|---|
| 2.1 | 画面のスクロールバックを目視 | clone コマンドに `ghp_` / `github_pat_` が**現れない** |
| 2.2 | `grep -r 'ghp_\|github_pat_' ~/.bash_history` | ヒットなし |
| 2.3 | `git -C ~/<repo> remote -v` | URL に認証情報が**含まれない** |
| 2.4 | `grep -r 'ghp_\|github_pat_' ~/<repo>/.git/config` | ヒットなし |
| 2.5 | clone 自体 | 成功する（`git credential-cache` 経由で認証） |

2.5 が失敗する場合はリモートに `git-credential-cache` が無い可能性がある。
`git credential-cache exit` がエラーにならないか確認する。

**旧バージョンからの移行**: 以前のバージョンで clone 済みのリポジトリを
開き直し、`git remote -v` から認証情報が消えていることを確認する。

## 3. 自動再接続

| # | 手順 | 期待する結果 |
|---|---|---|
| 3.1 | 接続中に機内モード ON → OFF | 自動で再接続し、tmux の内容が復帰する |
| 3.2 | Wi-Fi ↔ モバイル回線を切り替える | 同上 |
| 3.3 | ホームに戻る → アプリに復帰 | 自動で再接続する（iOS では毎回切れる） |
| 3.4 | 「切断」を明示的に操作 → 復帰 | **自動再接続しない**（意図した切断を尊重） |
| 3.5 | ホスト鍵ダイアログで「接続しない」→ アプリ復帰 | **再接続もダイアログ再表示もしない** |
| 3.6 | 圏外のまま放置 | 5回試行して止まる（無限リトライしない） |

3.5 は特に重要。ここが壊れているとダイアログが連打され、利用者の判断が
無効化される。

## 4. tmux によるセッション保持

| # | 手順 | 期待する結果 |
|---|---|---|
| 4.1 | `sleep 300` を実行し、機内モードで切断 → 復帰 | `sleep` が継続しており、残り時間から再開 |
| 4.2 | カスタム SSH サーバーでも 4.1 | 同じ（今回 tmux を適用したのはこちら） |
| 4.3 | tmux が入っていないサーバーに接続 | エラーにならず通常のシェルが使える |

## 5. 通知

| # | 手順 | 期待する結果 |
|---|---|---|
| 5.1 | 初回に通知を出す操作 | OS の通知許可ダイアログが出る |
| 5.2 | アプリを**背面**にして `sleep 10; printf '\033]777;notify;test;done\a'` | 通知が届く |
| 5.3 | アプリを**前面**にしたまま同じコマンド | 通知は出ない（画面を見ているので不要） |
| 5.4 | `printf '\033]9;short form\a'` | 通知が届く |
| 5.5 | 通知を拒否した状態で同じ操作 | 通知は出ないが**アプリは正常に動作する** |

**iOS の制約**: iOS はアプリをサスペンドすると SSH も止まるため、5.2 は
アプリを開いたまま別タブにいる場合のみ機能する。Android はフォアグラウンド
サービスがあるため背面でも届く。

## 6. リモートファイル編集

| # | 手順 | 期待する結果 |
|---|---|---|
| 6.1 | ターミナルで `cd ~/<repo>` してからファイルボタン | **そのディレクトリ**から一覧が始まる |
| 6.2 | ディレクトリを開く / 上の階層へ戻る | 期待通り移動する |
| 6.3 | 隠しファイルの表示切り替え | `.` で始まる項目が出入りする |
| 6.4 | テキストファイルを開いて編集し保存 | 保存され、ターミナルの `cat` でも変更が見える |
| 6.5 | 画像など**バイナリ**を開く | 「テキストファイルではない」と表示され、壊れた表示にならない |
| 6.6 | 512KB を超えるファイルを開く | 「大きすぎる」と表示される |
| 6.7 | 編集後に保存せず戻る | 破棄確認のダイアログが出る |
| 6.8 | 権限のないファイル（`/etc/shadow` など）を開く | エラー表示になり、クラッシュしない |

6.4 の逆方向も確認する。ターミナルで `echo x >> file` した後にエディタで
開き直し、外部の変更が読めること。

## 7. 難読化ビルド固有の確認

`app-release.apk`（minify 済み）でのみ確認する。以下は R8 がリフレクション
対象を削ると壊れる箇所。

| # | 手順 | 期待する結果 |
|---|---|---|
| 7.1 | Google サインイン | 成功する |
| 7.2 | サインイン後にアプリを再起動 | ログイン状態が保持される（secure storage が読める） |
| 7.3 | SSH 秘密鍵を保存するカスタム接続を登録 → 再起動 → 接続 | 鍵が読み出せて接続できる |
| 7.4 | バックグラウンドで SSH 維持（Android） | 常駐通知が出て、復帰後も接続が生きている |
| 7.5 | Web プレビュー | WebView が表示される |

## 8. 回帰確認（既存機能）

| # | 項目 |
|---|---|
| 8.1 | Settings のバージョン表示が pubspec の値と一致する |
| 8.2 | 利用規約・プライバシーポリシーのリンクが開く |
| 8.3 | 英語ロケールでエラーメッセージが英語で出る（通信を切って接続失敗させる） |

| 8.5 | ポートトンネル / Web プレビュー |

## 不具合を見つけたときに残す情報

- ビルド種別（debug / release）と端末・OS バージョン
- ターミナル画面右の「SSH ログ」の内容（接続系の問題の場合）
- `adb logcat` の該当部分（Android・debug ビルドの場合）
